# 发现面是采集面，不是在场面

局域网扫描视图保留在 v0.1.0，但被重新定义为**采集面**：它只负责把本机邻居缓存里出现过的 IP↔MAC 存进设备记录，**不对任何条目作在线/开机断言**；唤醒永远从设备记录发起。发现自己写（Linux 读 `/proc/net/arp`，macOS/Windows 跑 `arp -an`），不 fork `local-devices`，并连同它那套每张网卡每个 IP 的 port-80 主动扫描一起废掉。

让它诚实的关键是一条反直觉的事实：**残影持有的是那台机器正确的 MAC。** 已关机主机的邻居表残留记录，存的是它自己真实的硬件地址。所以「扫到就收藏」这条路径对残影是健壮的——收藏一个幽灵，得到的是一条**正确**的记录。活性信息因此完全不需要：扫描结果从不充当「现在该不该叫醒它」的依据，冲突在源头消失。

## Considered Options

- **删掉扫描视图**（我最初的推荐）。**被否，且我推翻它时用错了理由。** 我当时的论据是「邻居表里装不下你要唤醒的机器，睡着的机器可靠地不出现」。**这条作为物理事实是错的**：S3 休眠下网卡待机供电仍在，会继续回应 ARP（Wake-on-ARP），而 `ethtool` 把 `wake on ARP` 列为一级唤醒原因。使一台机器「可被 WoL 唤醒」的开关与使它「睡着时 ARP 可见」的开关是**同一个**，消费级网卡上默认开启。真正成立的理由是另一条——扫描结果没有在线断言的必要，而删除会砍掉设备记录唯一的**零输入**采集路径。
- **捡回那个「免费的可达性信号」**。`local-devices` 的 `pingServer` 无论成败都 resolve，`getChildren` 只留 `{ip, mac}`，信号被丢弃，捡回来在代码上极易。**被否**——port-80 探测会把「开机但未运行 HTTP 服务」的机器报成「不在」，而没有 Web 服务的桌面机与部分 NAS 正是最典型的唤醒目标。把「没探测到」呈现成「设备不存在」是**制造反证**，[002](0002-honesty-contract-for-wake-results.md) 明令禁止。
- **用三平台 NUD 过滤出「在线」条目**。被否，因为**没有任何平台支持它**：macOS IPv4 根本没有状态列（读 Apple 自己的 xnu `network_cmds/arp.tproj/arp.c`，`grep -ci 'reachable\|stale'` 为 **0**）；Windows `arp -a` 恰为三列无状态，`dynamic` 是**来源**分类（微软定义：TCP/IP 会话中自动增删）而非可达性，只有 `Get-NetNeighbor` / `netsh` 才有 NUD；Linux 的 NUD **按网卡独立缓存**，本机实测同一主机 `192.168.50.1 dev enp11s0 … REACHABLE` 与同主机 `dev wlp12s0 … STALE` 状态互相矛盾，故推不出**主机级**结论。
- **保留 port-80 主动扫描**。被否——每次树渲染 504 次 outbound connect（两张同 /24 网卡即 252+252，无接口去重），另有 1 分钟超时，VPN 的 /16 虚拟网卡会推到几万；且扫描流量本身会去敲目标主机的门，可能触发唤醒。一个只读视图没有任何理由持有这种代价。
- **fork `local-devices` 而非自己写**。被否——Q1 决定废掉主动扫描后，库剩下的价值不到百行（且它的 Linux 解析器是给 net-tools 括号输出写的，换 `arpPath` 不解决问题）。fork 要长期维护一个只用了极少部分的库。自己写是三个各约 20 行的解析器，无提权、无扫描、无第三方依赖。
- **保留扫到条目上的「唤醒」按钮**。被否——按采集面模型，唤醒永远从设备记录发起；在尚未保存、IP 可能已变的条目上发起唤醒会绕开耐久路径，且让发包层与诚实契约要在这条路径上再实现一遍。

## Consequences

- **唤醒调用路径从两处减为一处。** `LANEquipmentProvider.wake()` 原本是 `LANFavoritesProvider.wake()` 的逐行同构拷贝，两处都仍在引用 ADR 002 已删除的 `message.WakeSuccess` / `WakeFailed`（按 002 的约定，`I18n` 修好后未知 key 回退为 key 本身，不修则回退为空串）。去掉 Equipment 行的唤醒按钮顺手消掉了一个需要同步演进的调用点。
- **视图必须改名，且必须有一行不可操作的说明。** 「LAN Device」/「局域网设备」隐含在场断言。改为「近期出现的设备」/「Devices seen recently」，并在树的首行放一条不可操作说明，写明取自本机邻居缓存快照、可能含已关机主机的残留记录、保存到收藏后才是耐久唤醒入口。这同时把「残影」讲成一个**已知事实**而非看起来像缺陷。
- **发现不可用时不得显示空列表。** 空列表 = 把「没有证据」呈现成「有反证」。不隐藏视图（否则「为什么看不到这个视图」无从查证），改为在同位置显示说明项并写明失败原因与平台。
- **发现覆盖率因平台与硬件而异，规格不得承诺「能找到你的设备」。** ErP/深度睡眠 S5 会彻底切断网卡待机供电；Disconnected Standby（S0 Low Power Idle 缺席，或网卡缺 WoL 模式与协议卸载）把网卡置入 D3，它不回应 ARP；无线另论（WoWLAN 非同一机制，且发现只枚举 IPv4）。残影则近乎无界：Linux 回收器按**压力**门控（`gc_stale_time=60` 名不副实，实为 `gc_thresh1=128` 触发；本机表仅 4 条故残影事实上不被清理），macOS v4 的条目在断电后仍完整有效 20 分钟（`arpt_keep`），Windows 在 Stale 中持续存在。
- **只取 IPv4。** WOL 是 L2 广播，属 IPv4 域；`ndp` 是 IPv6，本次不引入。若将来引入，注意 `ndp -a` 的 `Prbs` 列为 0 时不打印，不可按位置切分。
- **跨平台解析规则**（写实现时按这些走）：macOS **必须**用 `arp -an`——BSD 原生 `arp` 不是 net-tools，无参数运行只打印用法并 `exit 1`；且源码 `arp.c` 的 `if (h_errno == TRY_AGAIN) nflag = 1;` 会**永久 latch**，一次 DNS 超时会把后续所有条目的主机名降级为 `?`。按**结构**匹配，**绝不匹配英文字面量**——Windows 与（部分）macOS 的表头会本地化（zh-CN 显示 `Internet 地址  物理地址  类型`）。Windows 的 `arp -a` 以空行开头、每接口一块、`Interface:` 行无缩进而表头与数据行恰好 2 个前导空格、**列宽随构建版本变化故不可按固定偏移解析**、MAC 为小写连字符。永不出现 `(->)` 记法（那是 `netstat -rn` 的东西）；`(incomplete)` 是 **MAC 占位符**（`sdl_alen == 0`）而非状态。
- **读邻居表在三平台均无需提权**，但 Linux 一侧已实测（`su -s /bin/sh nobody -c "ip neigh show"` 返回全表 `exit=0`；`/proc/net/arp` 权限位 `-r--r--r--`），**Windows/macOS 的读路径无特权要求仅为第三方共识，无厂商权威出处，规格须标注为待验证**。另需区分与 Unix 特权不同的另一层：沙箱化的 VS Code GUI 扩展可能被 App Sandbox/TCC 拒绝，与 UID 无关。
- **双网卡去重归解析层**：同一 IP+MAC 在两张网卡下会产生两行，按 `(IP, MAC)` 去重。**同一台设备因随机 MAC 出现多行不归此处**——那是身份键问题。
- **旧的行为不再成立，规格不得引用**：视图中「设备在线」的暗示、`local-devices` 三平台解析器的行为、以及「扫描能找到睡着的机器」与「扫描找不到睡着的机器」**两种说法都不成立**——前者因 Wake-on-ARP 而对，后者因残影近乎无界而不。
