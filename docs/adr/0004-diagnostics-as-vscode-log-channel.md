# 诊断面：用 VS Code 自己的日志通道，不自己写文件

扩展的可观测性由**一个 `LogOutputChannel`**（`createOutputChannel(name, { log: true })`）加上**一个「复制给维护者」命令**构成。前者是活的面，后者把当前通道内容连同环境信息（VS Code 版本、扩展版本、`process.platform`、`remoteName`、网卡清单）格式化成一段可直接粘贴的文本进剪贴板，**其中 MAC 截断到 OUI 三字节**。日志正文固定英文、raw code 原样，不跟随 `env.language`。记录站点为唤醒路径的 `.catch` 与 `useLocalStorage` 的两处持久化失败；discovery 站点不记（归 ADR 0003 的自研发现改造），i18n 激活失败单独记。

这张 ADR 存在的唯一理由是回答一个未来的读者必然会问的问题：**"为什么不干脆自己 `appendFileSync` 一个 `wake.log`？"** 因为 VS Code 已经提供了那件事的全部难点——跨会话落盘、级别、时间戳、以及一个不写代码就有的保留策略（`logsDataCleaner.ts:38-46` 保留最近 9 个会话），本机 `/root/.vscode-server/data/logs/` 下实测正好 10 个会话目录、最早跨越数周。自己重写一遍只会更差。

## Considered Options

- **自己写 `context.globalStorageUri/wake.log`（append-only、跨会话）**：这是本票第一轮的推荐，被自己的第二轮推翻。除了要重新发明级别与轮转之外还有两处硬伤。**一、保留策略一旦由我们写，就会在某天默默截断最旧的记录**——残留文本会冒充一份完整的历史，而"悄悄删掉证据然后让剩下的部分看起来完整"本身就是过度声明。**二、纯文本没有级别通道**：ADR 0002 已经写明 `timed-out` 与 `partial` 同级 Warning、**必须靠措辞而非颜色区分**，那前提是还有级别做粗筛；纯文本里 `sent` 与 `timed-out` 只差一个词。更毒的是**缺席的误读**——日志只在真有 `failed` 时才写下那两行，用户若从未触发（最常见的未确认场景恰恰是回调没回来），日志里就只剩一串 `sent`，"没有坏消息"会被读成"没发生问题"，而真相是扩展**从未拿到任何关于目标的证据**。这是 ADR 0003 那个错误的镜像版：不把没有证据呈现成反证，而是呈现成免除嫌疑。被否。
- **主动诊断命令「探测本机能否发送 WOL」**：只有两条路，都不成立。纯 `dgram` 下"本机能否发出 WOL"的唯一肯定证据就是**真的发一个包**——那会以诊断为名敲响整个广播域，叫醒域内所有开了 WoL 的机器；这正是 ADR 0003 亲手杀掉 port-80 扫描的同构罪，只穿了一件诊断服。而只枚举网卡再把输出标成"能力判定"是零信息的：`wakeonlan@0.1.0` 的 `sendToAll` 是 `Promise.all(promises)`，**零可用接口时它照样 resolve**（本机执行验证：`ZERO-IFACE RESOLVES WITH: [] -> .then() fires`），枚举根本区分不出"能发"与"一个接口都没有"。被否。
- **保留探测但改成显式签名**（用户手输一个 IP，逐条列出"这会唤醒 X 域"，确认后才发）：诚实，但它是第三个决策，且是全图唯一一个会打扰别人机器的决策。不在本票。被否，留作新地图的可能入口。
- **裸 `createOutputChannel(name)`**：`append` 在裸通道上不受级别过滤，于是失去了唯一能让 ADR 0002 的四级在日志里分开的机制。被否。
- **日志写进工作区**：`.gitignore` 只忽略 `out/dist/node_modules`，一个落在工作区里的日志文件会弄脏用户的 git 树。被否。
- **诊断包 ID + 上传**：没有任何遥测依赖、没有服务端、没有可关联的标识物。纯本地文件已经正好是维护者需要的东西。被否。

## Consequences

- **「日志」是一条新词汇，且它有边界。** 它是**发送方事实**的一种载体：可以逐行记录 `sent` / `timed-out` / `partial` / `failed` 与 raw code，但**不得跨越证据阶梯写下任何关于目标的东西**。GLOSSARY 的 **理由** 条目此前写着"原始码只进日志"而"日志"从未被定义——这个词是承重的，现予补齐。
- **必须有一条自我说明的边界。** 由于日志只在真的有记录时才写下某一行，**"日志里没有坏消息"不构成任何结论**。导出载荷的首尾行要写死这一点，否则 ADR 0003 已经废掉的错误会以反向形态复活。
- **级别过滤有两个会咬人的细节。** **一、LogOutputChannel 上的 `append` 与 `appendLine` 都被改写成 `info()`**，因此**受级别过滤**（`extHostOutput.ts:52-54`、`:93-95`）——裸通道上的 `append` 不受过滤，这个不对称极易踩。**二、过滤发生在写入时**，被拒绝的行**永远不会落盘**，事后调高级别也捞不回来。推论：`failed` 的证据行（raw code + `destination` / `source` / `packetCount`）必须写在默认级别上，否则用户调过级别后 `[查看日志]` 会为他唯一需要解释的那次失败弹出一个空通道。`channel.logLevel` 是 `readonly`，扩展无法自保。
- **channel 名即文件名，所以不能本地化。** 路径形如 `<userData>/logs/<YYYYMMDDTHHMMSS>/window<N>/exthost<M>/output_logging_.../<publisher>.<ext>.log`，实测同一扩展在不同会话落在不同时间戳目录，一个会话还可能含五个各自编号的 exthost。本地化 channel 名会把日志按 UI 语言切成多份文件。**这也正是"复制给维护者"命令存在的理由**：路径不可控是选择 (a) 的代价，而导出命令比"永远自己写一份"更便宜地把它解决掉了。
- **记录器不得先于被记录对象的行为修正而上线。** 零网卡时的假 `SENT` 归 #3 的自有发包层判定；但记录器一旦先落地，就会在一个尚未修好的缺陷上写下**持久的**假断言。同理 discovery 站点本票不记——在一条即将被删掉的代码路径（ADR 0003 的自研发现）上建日志等于给 `local-devices` 那个记忆化 reject 装录音笔，每次渲染重记同一个失败。
- **远程宿主。** `logs/` 与所有接口信息都在**扩展进程所在机器**上，也就是 GLOSSARY 的**发包位置**所在机器。#12 已裁定宿主形态的立场（[0005](0005-sending-position-disclosure-not-refusal.md)），本票不解决它，但导出载荷因此**必须标明它描述的是哪台机器**——以**机器身份**（hostname）为主，`remoteName` 降为辅助标注。判据是「这台机器叫什么」，不是「这个窗口被产品分成远程还是本地」：后者是宿主产品给窗口分的类，正是发包位置的定义明确排除的判据。
- **剪贴板载荷与落盘文件受众不同。** 文件留在用户自己机器上，可以是完整 MAC；剪贴板会进**公开 issue**，而 issue body 永久归档，因此 MAC 截断到 OUI 三字节（`a4:83:e7:**:**:**`，足以区分两张网卡、认不出是谁的）。
- **日志正文不本地化**是一个刻意的例外，需要写进规格：跟随 locale 会让不同语言用户的 bug report 无法互相 grep，且 `I18n.t` 对未知 key 返回 `''`，一个未迁移的 key 会产出**一行空白日志而不是一行缺失**。因此**日志文件不属于 ADR 0002 的"用户可见字符串"**，不适用两份 nls 的规则。
- **本票给 `package.json` 的 `contributes.commands` 增加了一个条目**，而 #14 正在裁定 `activationEvents`。#10 因此阻塞 #14。
- **尚未裁定：每个记录站点写在哪一级 `LogLevel`、行格式，以及失败时走 toast 还是走同一份诊断面。** 这些是下一个决策，不在本票内。
