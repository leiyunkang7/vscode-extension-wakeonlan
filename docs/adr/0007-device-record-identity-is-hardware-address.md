# 设备记录的身份是硬件地址，且它不携带任何观测到的地址

一条设备记录由三件事构成：**一个可选的名字**、**一个必填的硬件地址**、**一段可选的显式地址**（空即走隐式广播）。身份是那个硬件地址。记录里**不存 IP**——采集面观测到的那个地址不进耐久数据。

术语已入 `GLOSSARY.md`（**设备记录**），它与 **邻居条目** 成对：后者是观测的残留，前者是用户的决定。

这张 ADR 存在的理由是回答一个未来的读者必然会问的问题：**"发现视图里就摆着那个 IP，收藏时顺手存下来不是很自然吗？活性探测以后也要用。"** 不自然，因为那会把一个关于目标的命题冻进耐久数据。

## 为什么身份是硬件地址

不是惯例，是一条硬定义：**唤醒报文只携带硬件地址**，缺了它就没有可发之物。名字可以为空、显式地址可以为空，**硬件地址不能为空**——这是"身份"在本扩展里唯一站得住的含义。

否掉的两个候选：**名字**（用户自取、可改、可重；#15 已裁定它连日志都不许进，因为它的内容扩展无法预料，拿它当身份等于把「删哪一条」交给一个可编辑字符串）；**显式地址**（可空，且域名要到发送那一刻才解析，两条记录在字面上无法事先比较——一个可空又不可比较的东西当不了身份键）。

## 为什么查重只提示、不阻止

实测样本：同一台手机因随机 MAC 在邻居表里出现六行独立条目（`8e:c3:97:f8:18:6b` ×6）。随机地址轮换产生的是**真实不同的网卡地址**，每一个都是合法的唤醒目标——报文必须发到那个地址才唤得醒那块卡。所以「同地址已有记录」不是一次错误。

这是 [0005](0005-sending-position-disclosure-not-refusal.md)「不建拒绝机制」那条立场在**存储面的重述**：扩展没有能力判定两条同地址记录是否同一台机器，就不许它替用户判定。

**提示合法**的原因要说清，否则会被读成一次禁止：提示的内容是「你已经存过一条同样硬件地址的记录」——**这是发送方事实**（扩展知道自己存过什么），落在 [0002](0002-honesty-contract-for-wake-results.md) 允许断言的一侧，不涉及任何关于目标的命题。

残余代价照实写：**用户逐条收藏那六行，收藏里就是六行**，扩展不会也不能合并。地图「MAC 去重」那条迷雾的下半截到此只能停在"提示"——真正能减行数的是采集面按 `(IP, 硬件地址)` 去重，那已由 #8 定死。

## 为什么记录里没有那个观测地址

存下它就得到一个**会随时间变成假话的字段**，而它之后仅有的两条用途都不诚实：

1. **拿去单播** = 扩展替用户断言「这台机器现在在这里」。`GLOSSARY.md` 的边界条已经写了相反的做法：树行**显示**那个地址（观测），填入由**用户自己点**（决定）。
2. **拿去显示成"上次见于 …"** = 一个关于目标的命题，而 [0003](0003-discovery-as-capture-not-presence.md) 已定邻居条目在任何平台都答不出「这台机器醒着吗」，残影可无限期存在。

而它**没有任何正当用途**：`sendToBroadcast(mac)` 根本不需要地址；`sendToHost(mac, host)` 用的是用户填的显式地址；[0005](0005-sending-position-disclosure-not-refusal.md) 的同网段谓词只需要**显式地址的解析结果**。活性探测若真要进 v0.1.0，它应当带着自己的迁移方案回来，而不是现在就存一份会过期的观测。

## 名字不进任何机器可读行

名字是这条记录上唯一一个**扩展无法预料其内容**的字段（可能是姓名、手机号、位置名），而「复制给维护者」要服务的场景是**贴进公开 issue**。⇒ 通道正文与剪贴板文本都不带名字（完整硬件地址可以留在通道，那落用户自己磁盘；剪贴板按 0004 截到 OUI）。代价照实说：维护者认不出「用户说的客厅那台」，只能靠硬件地址对表。

## 代码命名本轮不动

规范词汇是 **设备记录**／**邻居条目**，但 `Favorite`／`Equipment` 这两个类名、它们的视图 id、7 条命令 id 与 `contextValue: 'favorite'` **不改**。理由是一条刚定下的不变量：票 #14 裁定视图 id 来自类 `.name`，且 `activationEvents` 必须与最终视图 id **逐字相同**——改名牵动 manifest 的 `views[].id`、类名、`activationEvents` 三处耦合外加一串 id，而**用户看不到 id**。成本全在耦合上，收益是零。

要改的只有**显示名**：#8 那条「视图改名去掉在场断言」本来就只要求标题不再声称在线，它落在 `%command.EquipmentProvider%` 这类 nls 值上，不动 id、不触 #14 的不变量。

## Considered Options

- **身份用名字或 `(地址 + 显式地址)` 组合** — 否，见上。
- **查重阻止重复添加** — 否，随机地址轮换是正当用法，且扩展无判定能力。
- **多存一个"上次观测到的 IP"** — 否，它会变成假话，且现有两条用途都不诚实。
- **彻底重命名代码以匹配规范词汇** — 否，成本在 #14 的三处耦合上，用户看不到 id。

## Consequences

- 这份记录**第一次拥有自己的数据形状**：今天落盘的六个字段全是 `vscode.TreeItem` 的 API 属性，没有一个自有数据字段（#13 已定 `iconPath` 不再持久化，#4 已定记录住 `globalState`）。
- 字段名与展示语义相反的那处（`label` 存 ip、`description` 存 MAC，而 `wol(equipment.description)` 把 `description` 当 MAC 传给发包层）随名字/硬件地址拆开而自然消失。
- 树行显示：`label` = 名字（空则回退硬件地址）、`description` = 硬件地址、`tooltip` = 完整记录。
- 记录继续住 `globalState` ⇒ #9 的迁移问题升为主路径；`remove()` 现存的「按单字段匹配、找不到时 `splice(-1,1)` 静默删掉最后一条」这条缺陷必须在实现时随身份键一起修掉（它是既有伤害，不是新决定）。
- 表单（#7）成为写入这份记录的**唯一通路**，且字段只剩三个（端口已由 #4/#6 判定不进记录）。
