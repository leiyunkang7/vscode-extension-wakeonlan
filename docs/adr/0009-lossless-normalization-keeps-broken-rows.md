# 旧数据无损归一化，坏行不丢

v0.0.3 的落盘数据是六个 `vscode.TreeItem` API 属性的 JSON dump；[0007](0007-device-record-identity-is-hardware-address.md) 已把它换成三个自有字段（名字可选、硬件地址必填、显式地址可选）。本 ADR 定死**怎么换**：加一个 schema 版本键，`normalizeDevice(raw)` 作为存储数据的唯一入口且**绝不注入默认值**，归一化失败的行按新形状保留为**未完成条目**（不可被唤醒，但呈现出来等用户补全），删掉 `useLocalStorage` 直接用 `context.globalState`，`setKeysForSync` 不开。

术语已入 `GLOSSARY.md`（**未完成条目**，及其同名边界）。

这张 ADR 存在的理由是回答两个未来的读者必然会问的问题：**"为什么 `normalizeDevice` 不给缺失字段补默认值？"** 和 **"为什么不合法的旧记录不直接丢掉？"**

## 为什么绝不注入默认值

往持久化记录里写默认值，会让「用户从没设过」与「这条记录解析失败」变得**不可区分**，并把迁移当时的那份全局默认**永久冻结**给每一条已归一化的记录。

这在显式地址上尤其要命：绝不给一条空的显式地址补一个猜出来的地址，否则 [0005](0005-sending-position-disclosure-not-refusal.md) 的同网段谓词会拿到一个从未有人确认过的地址——扩展于是替用户断言了「这台机器现在在这里」，正是 `GLOSSARY.md` 那条边界禁止的方向。

## 为什么不丢坏行

写进 `globalState` 的数据**不可重建**：不参与同步、不在版本控制、无法从任何地方恢复，装了多少个 v0.0.3 的用户未知。丢一行就是不可逆地弄丢一台用户正想叫醒的机器，而换来的好处只是树上少一种行形态。

「不可唤醒」不是「不存在」——扩展知道自己存了什么、缺什么，这是发送方事实，落在 [0002](0002-honesty-contract-for-wake-results.md) 允许断言的一侧。

**存储面因此保持单一形状**：未完成条目也按新形状写回，非法性是**推导**出来的（字段为空或校验不过），不是另存的标记位。否则就多出第四个字段，0007 的三字段当场破掉，而"唯一入口"的用意正是防止两种表示漂移。

## 为什么删掉 `useLocalStorage` 而不是修它

那三个缺陷——`getItem` 把缺失 key 塌缩成 `''` 使 `rawValue === null` 分支成死代码（对数字型默认值永久产出 `NaN`）、`read()` 走"写入默认值"分支时不赋值给 `data.value`、`:66` 的 `Array.isArray` 分支不可达——**全部来自同一个根因**：这个 hook 试图当通用持久化层，而 v0.1.0 的持久化面**只有一条设备列表**（[0006](0006-addressing-carried-by-device-record-not-settings.md) 已定设置面出局，[0004](0004-diagnostics-as-vscode-log-channel.md) 已定不提供 verbosity 键）。给唯一一把钥匙配一把万能锁，那把锁的 bug 都是锁自己长出来的。

票面反对"绕开"的理由是"要把配置也搬进 `globalState`"——**配置那一半已经不存在了**，这条反对在 0007 落地后自动失效。

## 可见性：迁移静默，待补全出声

丢弃四个字段（`collapsibleState` / `iconPath` / `contextValue` / `tooltip`）是每次升级都会重演的常规动作，每次弹窗只是在训练用户关掉通知 ⇒ 迁移本身只进日志通道。但**待补全不一样**：那是扩展在说「我这里有 N 条东西你得亲自处理」，属于用户不主动去看就一定会忘的那类 ⇒ 单独一条通知。

顺带确认一条既有硬失败：`iconPath.light` 经 `Uri.toJSON()` 落盘成普通对象，**扩展宿主一重启它就不再是 `Uri`**——按 API 契约这不是显示难看，是硬失败。

## 为什么不同步，但要写明不同步

不同步是 `extensionsSync.ts:397` 那个 `if (keys)` 的**显式闸门**，也就是说"不同步"从来是一次选择，只是这个扩展**遗漏了**做这次选择。规格里明写它是一次选择，只需一行"不调用"。

而开它要承担一个未实测的东西：[#17](https://github.com/leiyunkang7/vscode-extension-wakeonlan/issues/17) 已证实 `globalState` **恒落在窗口客户端**（与扩展跑在哪台机器无关），所以跨机同步**不会**造成"同一条记录两个发包位置"的正确性问题——真正分机的只有跨客户端。但 `setKeysForSync` **端到端从未实测**，而目的地是规格：规格不该开一道没测过的闸门。**这条"明写不同步"必须留在规格里**，否则下一个读者会以为"不同步"是存储的属性。

## Considered Options

- **校验不过就丢弃（静默或带通知）** — 否。不可恢复的数据，丢弃是不可逆伤害，而收益只是少一种行形态。
- **给缺失字段注入默认值** — 否，见上。
- **修 `useLocalStorage` 而不是删掉它** — 否，根因是通用层本身，见上。
- **加一个 schema 版本键之外的第四个标记位表示"未完成"** — 否，多出第四个字段会把 0007 的三字段打穿。
- **把落盘键名从 `favoriteList` 改成 `deviceRecords`** — 否，键名用户看不见，改名只给一次性迁移多加一步，与 0007"代码命名本轮不动"同源，收益为零。
- **开 `setKeysForSync` 做跨机同步** — 否，闸门未实测；且网络拓扑数据外流是它的直接后果，绕不开。

## Consequences

- **硬件地址是身份，但不是键。** 0007 一面定"身份是硬件地址"，一面定"允许存在多条同硬件地址的记录"（随机地址轮换产生的是真实不同的网卡地址，每个都是合法目标）。所以 `remove()` 现有的「按 `description` 匹配、找不到时 `splice(-1, 1)` **静默删掉最后一条**」必须随身份键一起修掉，而修法**不是**加第四个稳定 id（那会推翻 0007），是**按树行对象匹配**。
- 版本键让扩展能对**自己的存储**说一句发送方事实（「这份数据是 v0.0.3 形状，我已迁移过」）——它不需要任何关于目标的证据，所以永远为真。单靠惰性归一化则永远无法断言这一点，而票面自己点出了要害：「`globalState` 在加载时从不被复查」。
- **未完成条目在树上的形态由 #7 决定**，本 ADR 只保证它在存储面已是新形状且可被重新编辑补全。
- 「复制给维护者」文本与日志仍不带名字（0007），迁移通知同理。
