# 不做活性探测：肯定信号在扩展的运行时里构造不出来

v0.1.0 **不含任何活性探测**。证据阶梯顶端停在 `sent`；`responded` 那一格由 [0002](0002-honesty-contract-for-wake-results.md) 预留，本版本**不存在任何代码路径能写下它**。规格里必须明写「不做」以及「为什么这不是加一个设置项能解决的问题」，不得留白——留白会被实现者读成"待定"，而 `#5` 预留的那个槽正好邀请他去填。

这张 ADR 存在的理由是回答未来的读者必然会问的那句话：**"加个 ping / TCP 连一下确认机器醒了，很难吗？"** 难，而且难在四个各自独立致命的地方。

## 一、这不是新决定，是 0002 与 GLOSSARY 的推论

[0002](0002-honesty-contract-for-wake-results.md) 已钉死：`responded` 是「有正面证据，**v0.1.0 永不产生，仅预留**」。而探测的全部产品价值就是产生 `responded`。`GLOSSARY.md` 的**边界**第一节也早已写着「v0.1.0 不做任何探测，因此最上可达的一级只是"发送方事实"」。⇒ 本票没有推翻任何东西，只是把两处已经写下的话补上理由。

⚠️ 地图 Notes 里那句「活性探测做成**显式可选项**而非默认行为」是**图表期的水位表述**：它管的是「若上线，必须以 opt-in 形态上线」，不是「要上线」。本票据 0002 与 GLOSSARY 裁定 v0.1.0 不上线，Notes 那条约束**继续有效并随本条一起进入下一张地图**。

## 二、肯定信号需要选端口，而选端口就是赌

纯 Node（扩展的真实运行时是 **Node 24.18.1–24.21.0**，不是任何 v26）下唯一的候选信号是 TCP connect 轮询。它有两半，各自都不成立：

- **探到了能说什么？** 连上某个端口只证明「那台机器上有服务在听那个端口」，不证明「它是被这次唤醒叫醒的」——服务可能本来就开着。这不构成 `responded` 所需的正面证据，因为**没有时间上的因果关系**可用（唤醒与探测之间隔着几十秒，而扩展不知道该等几秒——0002 已定等待提示刻意不带数字）。
- **探不到能说什么？更不能说。** `ETIMEDOUT` 在「还在睡 / 防火墙 DROP / 地址填错 / 还没开机」之间**不可区分**，而目标的自发服务可能是**任意一个**：选哪个端口就是在赌用户那台机器开了什么。赌对了得到一个不可归因的肯定，赌错了得到一次**假反证**——把「没探测到」呈现成「不存在」，正是 [0003](0003-discovery-as-capture-not-presence.md) 亲手杀掉 port-80 主动扫描时用的那条理由，同构罪。

**票面那条「`ETIMEDOUT` 归入哪一级」因此无解，而且解不在措辞里**：0002 要求「没有证据」与「有反证」分开，而一次探测超时**两者都不是**——它没有给扩展任何新东西。既如此，它不配获得新的措辞，也不配新增一个证据等级。

## 三、走隐式广播的那部分目标，在定义上就探测不了

这是本票最锋利的一条，且它不需要任何新事实：[0006](0006-addressing-carried-by-device-record-not-settings.md) 与 [0007](0007-device-record-identity-is-hardware-address.md) 已定**记录里不存观测地址**，隐式广播的目标根本不带地址。于是：

- TCP connect 需要一个地址 ⇒ 探测**只能覆盖「用户填了显式地址」那一子集**，而填显式地址恰恰是少数、高级用法；
- **原生依赖也救不了这一半**：ARP 与 ICMP 同样需要一个目标 IP，raw socket 只是换个协议去问同一个不存在的东西；
- 而「一部分目标有结论、另一部分永远没有」这种**选择性沉默**，会被读成沉默那一侧出了问题——这是 0004 已经处理过的「日志里没有坏消息不构成任何结论」的镜像形态，只不过这次发生在 UI 上，比日志里更难纠正。

## 四、唯一能给出诚实信号的机制需要原生依赖，而那是一次独立的迁移

Node 的 `dgram` 只能开 udp4/udp6，开不了 raw socket。想要 ARP/ICMP 级别的信号就得引入需要编译的依赖。而 [0001](0001-bun-oxlint-oxfmt-typescript7.md) 刚刚把工具链收敛成「纯 `tsc -p ./`、无打包器、Bun 只做包管理与脚本运行」，并明确否掉了「`@vscode/test-cli` 取代手写 mocha runner」这类**不该混进当前工作的独立重构**。为一张可选的、且按第三节只覆盖少子集的功能，把需要编译的原生依赖塞进一条 Marketplace 分发的扩展——**代价与收益不成比例，且方向与已批准的收敛相反**。

## 顺带排除掉的两条

- **邻居表状态**：[0003](0003-discovery-as-capture-not-presence.md) 已定没有任何平台能从中推出主机级在线命题（macOS IPv4 无状态列、Windows 三列无状态、Linux NUD 按网卡独立缓存），且 `REACHABLE` 是缓存值（`gc_stale_time=60`），断电后仍可能保留；Wake-on-ARP 反而让**睡着**的网卡照样回应 ARP。这条路在别的票里已经堵死。
- **只探本机能不能发**（不碰目标）：[这个扩展需不需要一个诊断面](https://github.com/leiyunkang7/vscode-extension-wakeonlan/issues/10) 已裁定，理由记在 [0004](0004-diagnostics-as-vscode-log-channel.md)——纯 `dgram` 下唯一的肯定证据就是真发一个包（那是以诊断为名敲响整个广播域），而只枚举网卡是零信息（`sendToAll` 用 `Promise.all`，零可用接口照样 resolve）。

## Considered Options

- **默认探测**（唤醒后自动轮询）— 否，第二节与第三节，且直接违反 0002。
- **显式可选探测**（设置项打开，默认关）— 否。它绕不过第三节：opt-in 改变的是**是否赌**，不改变**赌什么**；且不改变「隐式广播目标无从探测」。
- **只在带显式地址的目标上探测** — 否，这是选择性沉默（第三节第三条），比完全不探测更糟。
- **引入原生依赖做 ARP/ICMP** — 否，第四节；且它同样需要一个目标 IP。
- **把 `timed-out` 的措辞升级成「已尝试确认但未得到回应」** — 否。没有新证据就不许改措辞，这是 0002 禁止规则的直接应用：新措辞会暗示「我们试过」，而扩展什么都没试。
- **规格里留白、等实现期再说** — 否。留白会被读成待定，而 0002 预留的 `responded` 槽恰好邀请实现者去填。

## Consequences

- **规格必须包含一句显式否定**：本扩展不探测目标的存活，且**这不是一个设置能解决的问题**——与「跨路由器的远程唤醒不在能力承诺内」同批写进「扩展不能做什么」那一节（地图 Out of scope 已明令：不得用跨路由器那条来关闭任何关于探测或发包位置的问题，三者是不同的失败原因）。
- **`responded` 槽与 `message.WakeResponded` 键按 0002 保留在文案表里**，但规格要钉一条**可核对的**不变量：**不存在任何能产出 `responded` 的代码路径**。这条不是风格约束——它防的正是「实现者看到枚举里有一格就顺手填满」。
- 0002 那张表在 v0.1.0 **恰好四级**（`sent` / `timed-out` / `partial` / `failed`），与 [#15](https://github.com/leiyunkang7/vscode-extension-wakeonlan/issues/15) 定死的 `info`/`warn`/`error` 三档一一对应；**`responded` 不进日志**，因为它永不产生。
- **探测若将来上线，必须带着这三样东西回来**，缺一不可：(1) 一个能建立时间因果关系的信号（唤醒与响应之间凭什么判定是这次唤醒叫醒了它）；(2) 观测地址的迁移方案（0007 原话：「活性探测若真要进 v0.1.0，它应当带着自己的迁移方案回来」）；(3) 对「隐式广播目标无从探测」的处理。它按 Out of scope 的规则以**新地图**返回，不作为本地图的续集任务。
- 本票关闭后，地图迷雾中「活性探测要不要进 v0.1.0」这一条**不再毕业**，改记入 **Out of scope**。
